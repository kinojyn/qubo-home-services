# Document 10: AI Project Memory

## DS Home Services

**Version:** 1.0  
**Status:** Permanent  
**Priority:** Critical

## Purpose

This document serves as the permanent memory of the project.

It records approved decisions, architectural principles, design constraints, long-term goals, and development rules.

Before starting any new task, this document must be reviewed.

If any future request conflicts with this document, ask for confirmation before making changes.

## Project Identity

**Project name:** DS Home Services  
**Project type:** Premium website for a local home services company  
**Primary goal:** Generate qualified leads and build trust  
**Long-term goal:** Evolve into a complete digital platform for booking and managing home services

## Project Mission

Create the most professional and modern home services website in the local market.

The website should make a small local company feel as organized and trustworthy as a modern technology business.

## Permanent Design Rules

- Never redesign approved sections without a request
- Never introduce random colors
- Never reduce whitespace
- Never add unnecessary decorations
- Never use heavy gradients
- Never use excessive glassmorphism
- Never sacrifice usability for visual effects

## Permanent UX Rules

- Always prioritize clarity
- Always reduce cognitive load
- Always make the next action obvious
- Every interaction should feel effortless
- Every page should guide the visitor naturally toward contacting the company

## Permanent Engineering Rules

- Always use TypeScript
- Strict typing
- Reusable components
- Clean architecture
- Scalable folder structure
- Readable code
- Performance first
- Accessibility by default

## Decision-Making Framework

When multiple solutions are possible, evaluate them in this order:

1. User experience
2. Maintainability
3. Accessibility
4. Performance
5. Visual polish

Choose the solution that scores highest overall.

## Change Management

If a requested change:

- Breaks consistency
- Reduces usability
- Duplicates existing functionality
- Conflicts with previous approved decisions

Do not implement it immediately.

Instead:

1. Explain the impact
2. Suggest an alternative
3. Request confirmation if necessary

## Workflow

For every new task:

1. Understand the request
2. Review relevant project documents
3. Identify dependencies
4. Explain the implementation plan
5. Suggest improvements if appropriate
6. Wait for approval if the change is significant
7. Implement
8. Perform the Quality Assurance Checklist
9. Generate a completion report

## Completion Report Format

Every completed task should include:

- Objective
- Files Created
- Files Modified
- Components Added
- Responsive Status
- Accessibility Status
- Performance Notes
- Known Limitations
- Recommended Next Step

## AI Collaboration Rules

Treat existing approved work as the source of truth.

Do not rewrite stable code unless requested.

Do not introduce breaking changes without explaining why.

If a better solution is discovered:

1. Describe it
2. Explain its benefits and trade-offs
3. Do not replace the existing implementation automatically

## Project Success

The project is successful when:

- Users trust the company
- Visitors quickly understand the services
- The website is fast and accessible
- The design remains consistent
- The codebase stays maintainable
- Future developers can extend the project without confusion

## Final Principle

Every decision should strengthen the product.

Every change should improve the user experience.

Every line of code should support long-term maintainability.

Build not just for today's launch, but for the company's future growth.

When in doubt, choose the solution that is simpler, clearer, more maintainable, and more valuable to the user.
